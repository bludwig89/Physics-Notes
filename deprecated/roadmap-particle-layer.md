# Roadmap — casim Particle Layer (lattice + four fields + stackable particles)

2026-06-05 - 18:21

## Goal (from next-steps.md "CASIM Structure")

One base lattice construct carrying the four fundamental field channels (EM,
strong, weak, gravity), with **particles as first-class, typed objects stacked
on the lattice** whose interactions run *through* those field channels:

1. A particle's type (its exact quantum numbers) decides which forces act on it
   — quarks see all four; charged leptons see EM + weak + gravity; neutrinos see
   weak + gravity only. The applicability matrix is **derived from charges, not
   declared per particle**.
2. Particle construction stacks modularly: scenario YAML lists particles the
   same way it lists field channels today; the engine wires the couplings.
3. The GUI shows particles on the lattice interacting through the fields, with
   live sidebar readouts of test values, field data, and per-particle data.

This extends the existing engine (`casim.engine`), it does not replace it: a
particle is implemented as a `Channel` (so checkpointing, observers, Tier-2
context coupling, and the GUI all work unchanged), plus a typed
`ParticleSpec` layer above it.

## Design

### 1. `casim/particles/` package

```
casim/particles/
├── spec.py      # ParticleSpec (exact quantum numbers, Fraction), registry,
│                # force-applicability matrix, charge conjugation (F53)
├── channel.py   # ParticleChannel — engine Channel wrapping audited matter
│                # kernels, coupling hooks per force
└── __init__.py
```

### 2. `ParticleSpec` — exact quantum numbers

All charges are `fractions.Fraction` (Tier-1 exact, same convention as FG-1/F53):

| field | meaning |
|---|---|
| `name` | e.g. `"e_L"`, `"nu_e"`, `"u_L"`, `"d_R"` |
| `kind` | `"lepton" \| "quark"` |
| `T3`, `Y`, `Q` | weak isospin, hypercharge, electric charge — **Gell-Mann–Nishijima `Q = T3 + Y/2` validated exactly at construction** |
| `colour` | `True` for quarks (SU(3) triplet) |
| `B`, `Lnum` | baryon / lepton number (Fraction) |
| `chirality` | `"L" \| "R"` |
| `mass` | F27 complex-mass parameter in lattice units (default 0) |

First-generation registry (8 Weyl species, the FG-1 anomaly-free content) plus
antiparticles generated by the F53 charge conjugation
`C: (T3, Q, Y) → (−T3, −Q, −Y)` — never typed in by hand.

### 3. Force-applicability matrix (derived)

`ParticleSpec.couples_to()` returns the force set computed from charges:

| force | condition | physics |
|---|---|---|
| `gravity` | always | couples to energy (F64 dielectric is matter-blind) |
| `em` | `Q ≠ 0` | U(1)_em minimal coupling (F68) |
| `weak` | `T3 ≠ 0` or `Y ≠ 0` | W coupling needs left isospin; Z/hypercharge needs Y |
| `strong` | `colour` | SU(3) triplet only |

So `nu_e` → {gravity, weak}; `e_L/e_R` → {gravity, weak, em}; quarks → all
four. **A scenario that requests a coupling the matrix forbids (e.g. lepton →
gluon) is refused at build time** — the modularity guarantee.

### 4. `ParticleChannel` — particles as engine channels

State = spinor wavepacket(s) on the BCC lattice; propagation by the audited
kernels, never reimplemented:

- lepton singlet: `(f, g)` via `ca_bcc.weyl_step_3d_bcc` (free) or
  `ca_wmu.covariant_weyl_step_3d_bcc` (with links).
- left doublet `(ν, e)_L` or `(u, d)_L`: 4 fields via the same covariant step
  (the E2E B1 pattern already in `casim.engine.coupled`).
- quark: colour triplet of spinors (3 × `(f, g)`); colour current
  `J^a = q† T^a q` contracted with the audited `ca_strong` Gell-Mann
  generators `T_GEN`.

Coupling hooks read partner field channels from the Tier-2 `context` per the
applicability matrix. **Coupling fidelity tiers** (per decision 2026-06-05 —
background coupling where no dynamical kernel exists yet, flagged in
readouts):

| force | P1 mode | mechanism |
|---|---|---|
| weak | **coupled** (two-way) | existing audited loop: isospin current sources W (`fermion_isospin_current` + `w_sourced_propagation_step`); accumulated A → SU(2) links (`su2_expmap`) act back in the covariant step |
| em | **source-only** | charge current `Q·J` drives the paired-photon curl (`ca_charge_coupling.maxwell_curl_step`); back-action (Lorentz force via U(1) phase links on the BCC step) is P2 — needs the F68 minimal-coupling link construction audited in 3D first |
| strong | **source-only** | colour current `J^a` drives the sourced gluon step (`ca_gluon`); SU(3) link back-action is P2 |
| gravity | **background** | particle propagates over a static F64 dielectric `K = exp(2GM/rc²)` from the `gravity_dielectric` channel; readouts report potential energy `⟨ψ|φ|ψ⟩`, local K at centroid, and predicted deflection. Dynamical matter-sourced K is research-gated (no finding yet derives ψ → K sourcing) |

Each particle's `observables()` reports: norm, centroid position, centroid
velocity, exact charges `(Q, T3, Y, colour, B, L)`, and the active couplings
with their fidelity tier — these are the sidebar readouts.

### 5. Scenario shape

```yaml
name: first_gen_interactions
lattice: {L: 16, topology: bcc, c_lat: 0.5773502691896258}
ticks: 60
channels:
  - {type: w_sourced,  name: w_field, fermion: electron}      # weak field
  - {type: particle,   name: electron, species: e_L_doublet,
     init: {center: [8,8,8], width: 1.5, k0: [0.5,0,0]},
     couplings: {weak: w_field, gravity: gmass}}
  - {type: gravity_dielectric, name: gmass, M: 1.0, sigma: 3.0}
observers:
  - {type: norm_conservation, every: 5}
  - {type: particle_readout, every: 5}
```

### 6. GUI sidebar (Phase P3, next session)

Extend `casim/gui/app.py` Qt dock: a per-particle panel (position, velocity,
norm, charges, active forces + tier) and a per-field panel (energy, propagator
class, K_max / deflection for gravity), refreshed from
`Channel.observables()` on the existing tick callback. Particles render in the
existing point cloud with per-channel colour; field overlays stay
checkbox-selectable (already shipped).

## Risks / notes

- **No new physics in P1**: every propagation/source call is an existing
  audited kernel; the layer is bookkeeping + wiring. Anything requiring a new
  derivation (EM/SU(3) back-action, dynamical gravity sourcing) is gated
  behind P2+ findings.
- Topology: particle kernels are BCC; `charge_photon`'s curl source is the BCC
  curl symbol on a cubic FFT grid — the EM source coupling therefore runs on
  the same grid as the existing `charge_photon` channel (cubic), matching the
  audited usage. Mixed-topology scenarios stay refused by `LatticeSpec`.
- Checkpointing: particle state is plain ndarrays in a dict → NPZ
  checkpoint/resume works with zero engine changes.
