**Target.** The residual F388's review surfaced (`docs/reviews/F388-review-2026-09-15.md`, [[F388-fermion-photon-coupled-channels]] §2): [[F384-conserved-bcc-em-current]]'s conserved current is purely `Ĉ(k)`-longitudinal *by construction*, and F384's own caveats already call the transverse part "free, unconstrained gauge freedom." Because `em_photon` sources its radiative sector only through the current's transverse part, this made the fermion→photon direction of Stage 4's coupled loop structurally unable to radiate, and left total momentum unconserved (`ΔP_field` machine-zero while `ΔP_matter` grows). This finding constructs, rather than arbitrarily assumes, a physically motivated transverse component that fixes that declared-open freedom — "constructs" because the transverse sector is genuinely underdetermined by continuity (§1, review-confirmed); what is forced (not a choice) is that the *specific* construction below cannot perturb continuity at all, and what is a judgment call (disclosed, not a derivation in the stronger sense) is *which* transverse field to use.

**The answer.** Continuity is *one* linear constraint per Fourier mode on `J̃(k)`, and it only ever touches the projection of `J̃(k)` along `Ĉ(k)` — the discrete continuity equation `ρ(t+1,x)−ρ(t,x)+iĈ(k)·J(k)=0` is provably blind to anything perpendicular to `Ĉ(k)`. So *any* `Ĉ(k)`-transverse field can be added to F384's minimal solution without perturbing continuity by so much as one bit (verified below: bit-identical, not merely small). The only physics question is which transverse field is the non-ad-hoc one to add, and the model already has a candidate that needs no new derivation: `em_current.bcc_naive_current` (`q·ψ†σψ`), the actual continuum Noether current of the free Weyl theory — the same bilinear the SU(2) isospin current and SU(3) colour current already use. §1 of F384 rejected it as the *whole* current because its **longitudinal** projection only closes discrete continuity to `O(a)` (the walk's fractional-shift hop is not what that bilinear assumes). That rejection never touched its *transverse* projection — continuity never tested that projection at all. Taking `noether_transverse_current` (the naive current's own `Ĉ(k)`-transverse part) and adding it to F384's `conserved_current` gives `full_current`: the current that fixes the declared-open freedom with the one bilinear this model already trusts, restricted to exactly the sector continuity never constrained.

This is the lattice analogue of the standard continuum Coulomb-gauge split: a charge's actual current has both a near-field/Coulomb (longitudinal) part and a radiative (transverse) part, and only the second sources outgoing radiation — continuity fixes only the first.

## 1. Derivation

For a Weyl 2-spinor `ψ=(f,g)`, write `bcc_naive_current`'s output as `J_naive = q·ψ†σψ` (the continuum Weyl bilinear, real `(3,L,L,L)`). Split it via the model's own projector, `em_photon_sourcing.split_transverse_longitudinal`, which already implements the `Ĉ(k)`-transverse/longitudinal decomposition used everywhere else in this sector (`solve_A_coulomb_3d`, `magnetostatic_B`, F387's sourcing fix):

$$J_\text{naive} = J_\text{naive}^{T} + J_\text{naive}^{L}, \qquad \hat{\mathbf C}(\mathbf k)\cdot \tilde J_\text{naive}^{T}(\mathbf k) \equiv 0$$

Define

$$J_\text{full} \;=\; J_\text{exact}^{L} \;+\; J_\text{naive}^{T}$$

where `J_exact^L` is F384's own `conserved_current` (the exact, minimal, purely-longitudinal solution of discrete continuity). Because `J_naive^T` is transverse by construction, `Ĉ(k)·J̃_naive^T(k) ≡ 0` at every mode, so

$$\rho(t{+}1)-\rho(t) + i\hat{\mathbf C}(\mathbf k)\cdot \tilde J_\text{full}(\mathbf k) \;=\; \rho(t{+}1)-\rho(t) + i\hat{\mathbf C}(\mathbf k)\cdot \tilde J_\text{exact}^{L}(\mathbf k)$$

identically — adding the transverse piece cannot change the continuity residual at all. This is not an approximate statement; it follows from the projector's own definition, and is verified directly (§2) to be bit-identical, not merely small.

**Why this is not degenerate.** A single-plane-wave (uniform-velocity, translation-only) spinor state has a spatially uniform `|ψ|²` and hence an identically static `ρ`, making *every* current construction here trivially zero — an uninformative limit, and also the reason `check_full_current` evolves the test packet a few ticks first rather than using the degenerate `g≡0` initial condition `check_conserved_current` uses for its own (continuity-only) purpose. Once `g` is genuinely populated (mixed in by the walk's own unitary, off-diagonal in `σ`), `J_naive^T` is a substantial, non-noise fraction of the current's total norm (measured **69%** on the evolved test packet, §2) — the discrete-lattice analogue of the textbook fact that a translating-and-internally-evolving (dispersing, mixing) wavepacket, not just a strictly uniform plane wave, is what actually sources radiation.

## 3. Consequence for the coupled loop — `F389-radiative-current-backreaction` (core, gate, 4/4 PASS)

When set, `em_photon` sources `E_T` from `em_current.full_current` instead of `conserved_current`; **at the single-tick, same-input level**, everything else (the `ρ`/`E_L` Gauss-law update, `B_L` never populated, F387's split-sourcing recipe) is unchanged, because those all read only `Ĉ(k)·J`, which this fix leaves untouched given the *same* fermion state (§1) — verified an exact, forced linear-algebra identity in review, not merely a small perturbation. ## 4. What this does **not** fix — the honest residual

**Exact momentum conservation is not achieved, and the reason is structural, not a tuning defect.** Measured directly at every doubling tested (`0.05→0.1`, `0.1→0.2`, `0.15→0.3`, `0.3→0.6`): `‖ΔP_matter‖` scales **linearly** in `g_lat` (doubling ratio `1.99`–`2.00` in every case) while `‖ΔP_field‖` scales **quadratically** (doubling ratio `3.99`–`4.01` in every case). The recovered fraction (`‖ΔP_field‖/‖ΔP_matter‖`) is therefore itself `O(g_lat)`, not `O(1)`: it grows from `1.9%` at `g_lat=0.05` to `70%` by tick 300 at `g_lat=0.5` in an extended (non-gated) run, but never reaches, and there is no coupling-strength or run-length regime tested in which it reaches, exact cancellation.

**Why the orders don't match.** In continuum classical electrodynamics with a *linear*, self-consistent Lorentz-force coupling, momentum conservation is exact and holds order-by-order automatically, because the matter's equation of motion and the field's equation of motion are two halves of *one* covariant action (`−J·A` the single interaction term), and the resulting stress-energy tensor's Noether identity `∂_μT^{μν}=0` is what actually does the work — it is not a perturbative accident. This model's two channels were **not** built that way: `gauge.minimal_coupling.u1_link_weyl_step_3d_bcc` ([[F385-u1-link-covariant-step]], the fermion's per-link Peierls-phase recoil) and this finding's `full_current` (the field's source) are two separately-derived, separately-audited numerical prescriptions, bridged together in `core.coupled`, not two halves of one single gauge-invariant lattice action. Nothing in that bridge enforces an order-matching Noether identity. Concretely: the fermion's recoil is `O(g_lat)` because it responds *linearly* to the self-sourced `A` (a genuine, and appropriate, Lorentz-force-like leading-order response); the field's momentum is `O(g_lat²)` because `E×B` needs *both* factors sourced, and only `E` is directly sourced each tick (`B` only appears after `Ω_pair` rotates some of that `E` into it, matching Faraday's law's own structure — `B` is never directly sourced by `J` in continuum Maxwell either). **Deriving both channels from one single gauge-invariant lattice action, so that a genuine discrete Noether identity forces order-by-order conservation, is a strictly bigger undertaking than either this fix or F385's per-link step individually, and is not attempted here.** This is the honest, disclosed limitation the task set out to either resolve or precisely characterize: it is the latter.

**A related, disclosed-but-not-gated numerical-stability observation.** Extending the self-sourced scenario to 300 ticks at `g_lat=0.5` (found in review of this finding's own work, not gated): field energy keeps growing without an obvious saturation over that window (`0.0016→0.29`, roughly monotonic, accelerating rather than levelling off), while the fermion's own norm drift stays small and bounded throughout (`-1.2%` to `-0.7%`, comfortably inside F385's own generous `0.5` stability bound) — so the system is numerically well-behaved (no blow-up, no NaN) in the tested window, but whether the field-energy growth eventually saturates, oscillates, or is a genuine runaway at stronger coupling or much longer runtimes is not established here. A future session extending Stage 5's own scenario work to longer runs or stronger coupling should check this directly rather than assume either boundedness or runaway.

## 7. Caveats

- **The recovered fraction (`~11%` at `g_lat=0.3`) is a property of this specific, modestly-parameterized configuration**, not a ceiling — it grows with both coupling strength and run length (§4), but stays bounded away from `1` structurally (the order-mismatch argument), not merely because this configuration is weak.
- **`noether_transverse_current` reuses `bcc_naive_current` unchanged** — it does not re-derive or re-audit that bilinear; it only adds a new, physically motivated *use* of its transverse projection, in the one sector (transverse) where F384 never made any exactness claim about it in the first place.
- **The 300-tick extended-run observation (§4) is not gated** — it used a larger, non-default `g_lat=0.5` and a run length well beyond the gate's own 20-tick window, purely to characterize the qualitative long-run behaviour; a future session wanting a gated numerical-stability bound at stronger coupling should design that as its own test, not read this finding's own numbers as such a bound.
- **Only the Weyl 2-spinor / U(1) sector is covered**, matching F384–F388's own scope. The massive Dirac case and the SU(2)/SU(3) sectors' own currents (which use the same bilinear pattern but were never checked against discrete continuity at all, per F384 §6) are untouched.
- **The exchange-bus `consumes()` blind spot F388's review also flagged** (`EmPhotonChannel`/`FermionEmChannel`/`WSourcedChannel`/`FermionDoubletChannel` naming their partner via `fermion=`/`photon=`/`w_field=` config keys `Channel.consumes()` did not recognize) is partially addressed: `core.channel.Channel.consumes()`'s recognized key set now includes `fermion`/`photon`/`w_field` (verified: `EmPhotonChannel(fermion="fermion_em").consumes()` now returns `("fermion_em",)` directly, not just via the graph's separate `_config_channel_refs` string-matching fallback; `tests/casim/test_exchange_bus.py`, 10/10, and the fermion-W-loop suite, 14/14, both re-verified green). **But this does not close the gap the review actually demonstrated**, on closer investigation: `core.graph.build_graph`'s `_config_channel_refs` fallback (pre-existing, added for an unrelated prior bug, F269) *already* independently supplies the same dependency edge for any config string matching a channel name, regardless of which key it sits under — so the edge between `em_photon`/`fermion_em` was already present in `sim.graph.edges` before this fix, with or without `consumes()` recognizing the key. The deeper, structural reason `graph.order_violations` stays empty for *either* registration order (verified directly, both ways, after this fix) is that `build_graph` resolves a genuine mutual-dependency cycle's internal order as *exactly* the declared/registration order by construction (`comp_sorted = sorted(comp, key=lambda n: rank[n])`, where `rank` is registration order) — there is no independent topological fact to check registration order against for a true 2-node cycle, so no order can ever be flagged as "wrong" by this mechanism, regardless of `consumes()`'s recognized keys. The "correct" order (photon before fermion, for the documented pre-tick/post-tick contract) is a matter of convention this bus design does not, and structurally cannot, verify on its own. Fixing that would need a different mechanism entirely (e.g., an explicit declared-order assertion on the coupled-channel classes themselves, checked independently of the generic topological-sort machinery) — not attempted here, and flagged precisely (not just "not attempted") for whoever picks this up next.

**Claim:** none — this is an engine-capability addition (a current construction and a coupled-channel option) plus a precisely quantified structural limitation, not a claim against established Standard Model/QM/GR/SR physics; no `docs/claims/` card is issued per D12's bar. It supplies Stage 5's own scenario work with a current that can genuinely radiate, and a precise, load-bearing caveat about what "momentum conservation" can and cannot mean for it without a deeper (not attempted here) unification of the two channels' derivations.
