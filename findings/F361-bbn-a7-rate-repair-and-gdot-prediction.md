## 2. The bug: a transcription error against the implementation's own cited source

F297 §2 named the source as "Smith-Kawano-Malaney 1993 analytic forms" and flagged the symptom (Li7/H $-92\%$ against the same published reference the other three species validate on) without diagnosing it. Smith, Kawano & Malaney (1993, ApJS 85, 219) is itself a set of updates to L. Kawano's public BBN code (LA-UR-92-3164, "NUC123"), so that Fortran source is the primary, checkable reference for the analytic forms this module claims to implement. It was fetched directly (`curl` from the raw GitHub mirror above — a full, byte-identical copy of `nuc123.f`, 4619 lines) and compared term-by-term against `_rate_fits`. ## 3. The fix, and why it is a repair rather than a new derivation

The five fits were rewritten to the exact NUC123 sum, including the resonance-narrowed auxiliary temperatures $t_{9a},t_{9d},t_{9e},t_{9f}=t_9/(1+c\,t_9)$ that the pre-repair code had silently dropped (each is scoped to the one reaction that uses it, matching the source). This is external nuclear data transcribed correctly, not a new physics claim — the same status the passage already carried in the module docstring, now honoured.

The pre-repair forms are kept in the code, gated behind `legacy_a7_bug=True`, **solely as the control** that proves the repair is load-bearing (§4). They are not a second physical option. (The attack-and-fix pass, §9, also found and fixed a plumbing bug: `check_k2`'s top-level `Y_p`/`D_H`/`Li7_H` convenience fields were not threading `legacy_a7_bug` into their own `run_bbn` call, even though `validate_network` was — so `check_k2(legacy_a7_bug=True)['Li7_H']` silently returned the *repaired* number even while its own `checks` array correctly flagged K2-13 red off `validate_network`'s properly-flagged value. Fixed; both paths now agree, verified in §9.)

$Y_p$, D/H and $^3$He/H are **not bit-for-bit identical** — F361's first draft claimed they were, and that claim did not survive its own attack-and-fix pass (§9, attack 3). This is a single coupled 8-species network solved implicitly at each timestep (`_network_step`), so a change to any of the five $A=7$ rates perturbs the whole abundance vector at some order through the linear solve, even for species not directly involved. The perturbation is tiny — $3\times10^{-9}$ for $Y_p$, $2\times10^{-7}$ for D/H, $1.9\times10^{-5}$ for $^3$He/H, all many orders of magnitude below the 3%/5%/2.5% reference offsets and further still below the $2$-$3\sigma$ observational bands K2-1/K2-2/K2-7/K2-11/K2-12 check against — so no pass/fail verdict moves, but "unchanged" was the wrong word for what is actually "unchanged to $10^{-9}$-$10^{-5}$ relative." $^3$He/H moves the most because $^3\text{He}(\alpha,\gamma)^7\text{Be}$ (repaired) is the direct depletion channel competing for the $^3$He inventory.

Li7/H moves by more than an order of magnitude, from $-92\%$ (excluded from any check) to $-6.28\%$ — inside a declared $\pm10\%$ validation band (`LI7_VALIDATION_TOL`). That band is a round number chosen to sit comfortably (about $1.6\times$) above the observed $-6.28\%$ residual, deliberately looser than the $Y_p$ (3%) / D/H (5%) bands because a five-species, resonance-dominated secondary chain is intrinsically harder to hold to the same digit as the two-body $A\le3$ captures — but it was **not derived from an independent error budget**, and this finding does not claim it was; the attack-and-fix pass (§9, attack 4) flagged this honestly rather than dressing a round number up as principled. Li7/H is now included in `check_k2` as **K2-13** and `validate_network()` returns `Li7_validated: True`.

**The control.** `check_k2(legacy_a7_bug=True)` reproduces the pre-repair behaviour exactly (Li7/H rel. err. $-92.2\%$, verified via both `validate_network` and, after the §3 plumbing fix, `check_k2`'s own top-level fields) and turns **only** K2-13 red — 12/13, every other leg staying green. This is the record's declared failure mode (`casim test --id F361-bbn-a7-repair --param legacy_a7_bug=true`), satisfying D9's can-fail requirement with a control that isolates the exact leg the repair targets.

**What this is not.** The famous (observational) lithium problem — standard BBN's own $(^7\text{Li/H})_\text{BBN+CMB}\approx4.94\times10^{-10}$ against the Spite-plateau measurement $\approx1.6\times10^{-10}$, a factor-of-3-4 disagreement documented across the field (independently confirmed during this finding's attack-and-fix pass against the September 2025 review at [arXiv:2508.09821](https://www.aanda.org/articles/aa/full_html/2025/09/aa54482-25/aa54482-25.html), and the 2026 reassessment of $^7$Be weak/radiative rates at [arXiv:2601.12438](https://arxiv.org/html/2601.12438)) — is a disagreement between the *standard* BBN prediction and *observation*, and is untouched by this finding in either direction. What was broken here was this implementation's own reproduction of the *standard* prediction; that the standard prediction itself is in tension with the Spite plateau is a fact about the field's nuclear-rate uncertainties in the $A=7$ chain (both cited reviews point at $^7$Be destruction/conversion channels as the live uncertainty), not about this model.

## 5. $\dot G/G\equiv0$: a BBN-internal consistency check, not a new bound

F284 derives $\dot G/G\equiv0$ exactly (F79's structural $G$ on F283's rigid substrate) and compares it to the Hofmann–Müller 2018 LLR bound $|\dot G/G|<1.5\times10^{-13}\,\text{yr}^{-1}$ — a genuine zero-free-parameter prediction, met by an external, independent *measurement*, three orders inside it. F297 §10.4 asked for the same idea to be registered *in the BBN context specifically*.

**What this finding adds, honestly scoped after the attack-and-fix pass (§9, attack 1).** Every leg of `check_k2` runs at one fixed $G=$ `model_G()` across the entire BBN epoch — there is no $G(t)$ term anywhere in `hubble_rate`, so the code is structurally incapable of producing a $\dot G\ne0$ result even if one were true. That is the honest limit of this leg: unlike LLR, which *measures* $\dot G/G$ and could in principle have come back nonzero, this BBN calculation *assumes* $\dot G/G=0$ by construction and then checks whether the resulting $Y_p$/D/H match data. Passing K2-1/K2-2/K2-7 therefore shows the assumption is **consistent with** the light-element data, not that BBN has independently *measured* $\dot G/G$ and found zero. `gdot_over_g_prediction()` states this distinction explicitly and is named a "consistency check," not a "confirmation," in this revision.

**What was tried and discarded.** The obvious way to make this quantitative — perturb $G$ in `run_bbn` and invert the network's own $Y_p$ margin into "the $|\Delta G/G|$ this network bounds" — was implemented and then removed from the finding's claims. $Y_p$'s sensitivity to $G$ at fixed $\eta_b$ is weak enough ($dY_p\approx8.7\times10^{-4}$ per 1% shift in $G$) that inverting even a $1\sigma$ margin gives a $G$-shift of order unity, far past where the linearisation — and the entire non-relativistic weak-freeze-out treatment — remains valid. Reporting that number as "the bound BBN implies" would have been a bigger number attached to a smaller, unsound claim; `gdot_over_g_prediction()`'s docstring records the discarded attempt so a later session does not repeat it.

## 7. Verdict
