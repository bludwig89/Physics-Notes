## Engineering decisions (D1–D12)

*These are **engineering** decisions, recorded here because the same file is the human narrative that `docs/theory/supersessions.yaml` is the machine face of. They reverse no physics: every decision above stands unchanged, `complex128` and the $10^{-12}$ `machine` gate are untouched. D6–D11 come from `docs/roadmaps/roadmap-casim-consolidation.md`; D12 was added 2026-08-04; D1–D5 from `docs/roadmaps/roadmap-unified-program.md`. Completed 2026-07-31 - 18:20 at roadmap phase C9; the D2 reversal is ledger record `S8-D2-reversed-casim-is-the-program`, kind `methodology`.*

**D1 — BCC is the canonical lattice.** The body-centred cubic lattice with its $O_h$ point group is the base layer; simple-cubic code is retained as the continuum-limit regression target (`casim.engine.lattice.cubic`), explicitly labelled a reference implementation. *Stands unchanged.*

**D2 — ~~The flat `ca_*.py` kernels remain the single source of truth.~~** **REVERSED by D6, 2026-07-31.** D2 held that `casim` was a layer above an untouched kernel directory. It bought safety at the cost of a permanent seam: two trees, ~74 independent definitions of $c_\text{lat}$, six test-invocation conventions, and 268 test files reaching across the seam by `sys.path` insertion. P1's committed result baselines now supply that safety directly, so the seam had no remaining justification.

**D3 — Two co-equal interfaces.** The Python API and the CLI/scenario layer are peers; neither is a wrapper around the other. *Stands unchanged.*

**D4 — Device-agnostic backend.** Numerics dispatch through a protocol with a numpy implementation; a second backend (MLX/CuPy) ships as an extra, never a hard dependency. *Stands unchanged, and is now the `casim.numerics.backends` surface D8 owns.*

**D5 — Foundations first.** Provenance and a suite that can fail come before restructuring. *Stands unchanged — it is why C0–C9 were safe to execute.*

**D6 — CASIM is the program.** All 124 kernels and 47 forks live under `src/casim/engine/`, organised by sector on the D1 base layer: `core/`, `lattice/`, `gauge/`, `particles/`, `interactions/`, `forks/<sector>/`. The legacy flat-kernel directory and its 171 deprecation shims were deleted at C9, and `src/casim/__init__.py` no longer requires that directory to exist. The pre-clean original of every migrated file is in `deprecated/code/`; the per-file record — target path, sector, findings, dead symbols stripped, baselines re-run — is `docs/design/module-migration-manifest.yaml`, which stays live as the migration's provenance record.

**D7 — The constants registry owns values, not just provenance.** Modules import from `casim.constants`; literals are deleted. Exact constants resolve from closed form, not a truncated decimal — $a/\ell_P=\sqrt{8\pi}\,3^{1/4}$, $c_\text{lat}=1/\sqrt3$, $\delta^*=\tfrac29$ as a `Fraction`, $G_\text{LATTICE}=1/(72\pi)$. The consistency test asserts the *converse* of what it used to: not "every recorded site agrees" but **"no unregistered literal matching a registry value exists in `src/`."** Three cases deliberately keep more than one entry, because collapsing them would turn a prediction into an input: $f_\pi$ (model anchor / PDG target / $\Gamma$-convention), $\sin^2\theta_W$ (F45 UV $\tfrac14$ / F49 on-shell $\tfrac29$), $\cos3\delta^*$ (derived / empirical — the gap **is** the F256 near-coincidence). `alpha_eff_star` stays a bracket $[0.376,0.411]$ with no scalar value. A module that must *compute* a constant because the derivation is the physics under test declares a `MeasuredConstant` with a reason — enumerated, not allowlisted by regex.

**D8 — `casim.numerics` is the only numerics surface.** No physics module imports `numpy`, `scipy`, or an FFT library directly: `from casim.numerics import xp, fft, linalg, rng`. The façade is simultaneously the device seam D4 needs and the place to own hand-written primitives when a vendored one misbehaves — **chiral transforms are the known hazard**, so the equivalence contract specifically covers real/imaginary preservation, alongside all-libraries-agree-to-$10^{-12}$, round-trip identity, and thread-count independence. `tools/audit_numerics.py --ratchet` counts direct imports and only lets the number fall.

**D9 — Tests are declarative registry entries, not standalone scripts.** A record in `tests/registry/*.yaml` names its module, entry point, parameters, kind, tier and expectation; `casim test` is the only runner and `tests/conftest.py` generates pytest items from the same records, so `pytest` and `casim test --tier gate` cannot diverge. Four kinds, two result contracts: `assertion` (returns bool/raises), `result_dump` (baseline diff against git HEAD), `scenario` (a YAML run with `expect:` gates), `legacy_script` (declared debt, ratcheted to zero). Because a record names an *entry function*, physics-at-import is impossible by construction rather than by discipline. `casim test --param k=v` re-runs a record at a perturbed value, which makes sweeps a first-class operation.

**D10 — Cleanup and migration are one operation.** One touch per file: the original is copied to `deprecated/code/` as the backup, the cleaned copy lands at its engine path, the named baselines are re-run, and **any drift aborts and rolls back**. Bit-identical was the bar. `git` carries history; the copy guards against a bad *clean*, which is the real risk — P0 found that of 14 files an audit called superseded, exactly one was superseded wholesale and eleven were a dead verdict wrapped around load-bearing algebra. Hence the standing rule: dead-code detection **proposes**, a human **accepts**, per file, and when in doubt a module is migrated with a banner rather than deleted.

**D12 — Every claim that extends established physics has a card.** `docs/claims/CL{NNN}-{slug}.md`, one per assertion, with closed vocabularies for `tier / kind / status / domain / exactness / falsifier / review_state`; `tools/check_claims.py` enforces them at `make gate`. **A claim is not a finding.** A finding is a research record — written once, superseded rather than rewritten, and correct to keep saying what it concluded. A claim has a *present tense*: it can be narrowed, made contingent or withdrawn without touching the finding that produced it, and the card is where that change gets written down. The project was carrying only one of the two objects, and the symptom was `papers/Claims-and-Falsifiers-Summary.md` — a prose document whose revision 2 withdrew a core claim and four falsifiers in a blockquote, and whose revision 3 said revision 2 was wrong about charge quantisation in a second blockquote. Both corrections were right; **neither was checkable, discoverable from the finding, or countable.** Generation runs *backwards* from every other registry here — the card's front matter is the record, `docs/claims/registry.yaml` is generated from the cards, `claims-index.md` from the registry — because a module cannot carry its own metadata whereas a claim's prose and its metadata are the same object; splitting them would produce exactly one thing, a card whose status disagrees with its registry row. The rule that does real work: **a `status: live` card fails the gate when *every* finding it rests on is named in a `superseded:` list in the ledger**, which is the machine-checkable form of "overstated". It deliberately does *not* fire on a partial supersession — the P0.4/D10 lesson is that almost nothing here is superseded wholesale, and a check that flagged partials would train people to ignore it. Seeded 2026-08-04 with 251 cards (28 authored, 223 `unreviewed-seed`); `docs/audits/consolidation-plan-2026-08-04.md` records the eight findings judged **not** to clear the bar, so "no card" is a decision rather than an omission.

**D11 — Every module is registered.** `casim.engine.registry` records each module's name, sector, findings, exactness class, reachability (`reachable_from`, per channel) and test dependents. This is what `casim index` (C8) consumes, and it turns the old "≈67 kernels look unreachable" survey into a queryable field with a definition attached.

### What this changed about working in the repo

- **The legacy flat-kernel directory does not exist.** Nothing imports a bare `ca_*` name. `ca_bcc` is `casim.engine.lattice.bcc`; the manifest maps all 171 old paths to new ones.
- **`make gate` is the barrier**, and it lost four checks at C9 with the tree they guarded (migration-manifest coverage, the migration tool's self-test, the C3.4 shim-import check).
- **Every generated index comes from the registries**, not a filesystem scrape: `casim index` (or `make indexes`), `casim index --check` in the gate.
- **Forks keep their falsification value.** A rejected fork is a recorded negative result, carried into `engine/forks/<sector>/` with a status, not deleted. Forks are loaded by file path or bare name, never as package submodules, so `casim.FORK_DIRS` puts the sector directories on `sys.path`.
