## The claim, as the reviewer understands it

This is a scoping decision, not a numeric or physics claim, so the standard claim card does not apply. Restated neutrally:

- **DECISION** Part C of `docs/roadmaps/photon-fermion-coupling-rerun-prompt.md` (build a genuine 3D BCC DEC curl complex alongside `bcc_curl_symbol`) is not attempted this session; the session stops after Part B (F393) plus, per the finding's own framing, continues to Part D without it.
- **REASONS GIVEN** (1) the BCC lattice's 8 fractional body-diagonal hop directions make the plaquette construction a genuinely new geometric object, not a mechanical port of the existing 2D `discrete_curl_z`/`discrete_div` pair; (2) the verification program the roadmap's own Part C text demands (gate both `d∘d=0` identities to machine precision, then measure blast radius against five named consumers before switching anything) is itself a multi-step undertaking that would compete with Part D's budget; (3) Part D (the roadmap's actual point) does not require Part C to land, per the roadmap's own explicit text.
- **AUTHORIZATION CITED** the roadmap document itself pre-authorizes exactly this stopping point ("If the BCC DEC complex turns out to be more than this session can carry, stop after Part B and say so").
- **WHAT IS NOT CLAIMED** that the DEC route is wrong, unnecessary, or unlikely to succeed; that `bcc_curl_symbol` is fixed or should be changed; that the Weyl-vs-Dirac question is settled.
- **FORBIDDEN** none in the usual sense (no script/results JSON exists to avoid), but I read the finding itself only after forming an independent view from the audit, the research-review sections on DEC and Nielsen–Ninomiya, and the roadmap's own Part C/Part D/FLAG text, per the task's instructions.

## Independent assessment (in place of blind re-derivation)

There is no number to re-derive, so the adapted Step 2 is: given the same background material, would an independent reader reach the same "defer" conclusion?

**Reason 1 (novelty of the geometry).** Verified against the actual code. `charge_coupling.discrete_curl_z`/`discrete_div` (`src/casim/engine/gauge/charge_coupling.py:78-97`) is exactly what the finding says — an axis-aligned, integer-bond, forward/backward-difference plaquette curl on a square lattice, with an obvious oriented-boundary convention. The BCC lattice's own hop structure (`BCC_DIRS`, all `(±1,±1,±1)` combinations, i.e. the 8 body diagonals) is not axis-aligned and has no analogous "obvious" plaquette — confirmed by reading `weak_wmu.py:66-71` directly. The research review's own citation for the non-cubic case (the FCC/BCC DEC-FDTD paper) is flagged `[unverified]` in that document, meaning even the nearest published precedent has not been confirmed to solve exactly this problem. **Independently reached the same conclusion**: this is a real geometric research question, not a copy-paste extension.

**Reason 2 (cost of the verification program).** The roadmap's own Part C text (lines 112-118 of the rerun-prompt) is unambiguous that landing this correctly requires: building the complex as a *new* object (not replacing `bcc_curl_symbol` in place), gating both `d∘d=0` identities to `~8.9×10⁻¹⁶` to match the 2+1D prototype, and then running every one of five named consumers (`solve_A_coulomb_3d`, `magnetostatic_B`, `maxwell_curl_step`, `em_current.conserved_current`, `em_photon_sourcing.split_transverse_longitudinal`) against both symbols and reporting the blast radius *before* switching anything. That is a second research-and-verification arc on top of Part D's six-stage re-run. Reading the same text independently, this reads as a fair, non-inflated cost estimate — if anything the roadmap's own words ("a research session of its own," quoting the audit's §9) go further than the finding does.

**Reason 3 (nothing in Part D depends on it).** The roadmap's Part D header states this explicitly ("Only after Part A lands (Part C optional — if it does not land, say so explicitly...)"), so the finding is not asserting this on its own authority — it is quoting the plan. More importantly, this claim is not merely asserted: it is **empirically settled** by the same session. `findings/F395-stage5-circular-beam-rerun.md` — present as an untracked file in the working tree at review time — is exactly the Part D, Stage 5 re-run, done *after* F394's deferral, with Stages 0-4 re-verified bit-identical and Stage 5 re-measured against the fixed beam. Part D did not stall for want of Part C. This is about as strong a confirmation as a scoping decision can get: the predicted consequence of the decision was tested by the same session's later work, not just claimed.

**Conclusion of the independent assessment:** given the same background material, I reach the same "defer" conclusion for the same three reasons. This is not a rationalization to skip hard work — the hard work in question (a novel non-cubic DEC complex with a five-consumer verification program) is real, correctly characterized, and the session's own subsequent output (F395) demonstrates the deferral did not stall the roadmap's actual objective.
