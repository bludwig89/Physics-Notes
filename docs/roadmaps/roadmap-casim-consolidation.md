# Roadmap — CASIM Consolidation (C0–C9)

*Created 2026-07-30 - 09:30. Companion to `docs/roadmaps/roadmap-unified-program.md` (P0–P6), whose **P0 and P1 are complete** — see `docs/status/P0-completion-overview.md` and `docs/status/P1-completion-overview.md`.*

*This roadmap covers the arc the P-roadmap deliberately deferred: **collapsing the two-layer structure into one program.** It supersedes decision D2 and absorbs P2.2–P2.4 and P1.3.*

---

## 1. Purpose

**End state:** `src/casim/` is the whole program. There is no `ca-simulation/`. Every physics module lives under `casim.engine`, organised by sector on a BCC base layer. Every constant comes from one registry. Every numeric primitive comes from one façade. Every test is a registry entry run through `casim test` with declared parameters. Every index is generated by `casim index` from those registries rather than scraped from the filesystem.

The P-roadmap built the *instruments* — provenance (P0), a suite that can fail (P1). This roadmap uses them to do the structural work that was too dangerous without them.

## 5. Phases

Each phase below is written as a **standalone Claude session brief**. A fresh session should be able to open this file, read only its own phase, and work. Every phase has the same five parts: *entry state*, *read first*, *deliverables*, *acceptance gate*, *handoff*.

> **Standing rules for every phase**
>
> 1. **Baseline-first.** Nothing is restructured until `make drift` is clean on the affected artifacts. Bit-identical is the bar; a real tolerance change is recorded in the manifest with a reason, never absorbed silently.
> 2. **`make gate` green before and after.** No phase ends with a red gate.
> 3. **Ratchets only go down.** `tools/audit_tests.py --ratchet` and the new C1/C7 ratchets fail on regression.
> 4. **Write the changelog entry** (`docs/status/changelog.md`, one paragraph, timestamped `yyyy-mm-dd - hh:mm`) and **regenerate indexes** before ending the session.
> 5. **New findings** go to `findings/F{N}-name.md` — check the max F-number first (concurrent-session collisions have happened three times).

### C0 — Migration instrumentation

*One session. Moves no physics. Builds the four tools every later phase depends on.*

**Entry state:** P0 and P1 complete; `make gate` green; `deprecated/code/` and `deprecated/tests/` do not exist.

**Read first:** this file §2–§4; `docs/status/P0-completion-overview.md`; `docs/status/P1-completion-overview.md`; `tools/gen_manifest.py`; `tools/audit_tests.py`; `docs/theory/supersessions.yaml`.

**Deliverables**

**C0.1 — Reachability and import graph.** `tools/gen_module_graph.py`. AST-parse (never import — P0.2's rule, for the same reason) every file in `ca-simulation/`, `ca-simulation/forks/`, `src/`, and `tests/`. Emit `docs/design/module-graph.json`: for each module — its imports, its importers, which channels reach it, which tests reference it, which result artifacts it produces. This settles P6's "~67 of 106 kernels have no path from any channel" with a number that has a definition attached.

**C0.2 — Dead and superseded code detector.** `tools/find_dead_code.py`. Three independent signals, reported separately, never merged:

- *Structurally unreachable* — module-level symbols with zero importers and no `__main__` path.
- *Superseded by ledger* — symbols named in `docs/theory/supersessions.yaml`'s `code:` fields. Known targets: `ca_maxwell`'s σ-bilinear photon construction, the F50/F52/F62 rest-mass gravity path, `ca_raytrace.py:91`'s `F114_enlargement_pct`, `gluon_rotation_step_spectral_bcc_chiral`, F179/CN3 shape code.
- *Suspected dead* — reached only from tests that are themselves tombstoned.

Output is a **proposal**, not an action. A human (or the C4–C6 session) accepts each line. Nothing is auto-deleted; P0.4 already demonstrated why — of 14 files an audit called superseded, exactly one was superseded wholesale.

**C0.3 — The migration manifest.** `docs/design/module-migration-manifest.yaml`. One record per file, all 171:

```yaml
- source: ca-simulation/ca_bcc.py
  target: src/casim/engine/lattice/bcc.py
  sector: lattice
  phase: C3
  status: live              # live | partial | dead | superseded
  findings: [F41, F175, F264]
  exactness: exact
  dead_symbols: []          # from C0.2, human-accepted
  tests: [tests/findings/test_F264_bcc_bz.py, ...]
  baselines: [test-results/bcc_shells.json, ...]
  numerics_sites: 14        # np./scipy. call sites to migrate under D8
  constants_sites: [c_lat, a_over_lP]
```

**This manifest is the roadmap's real product.** C1–C9 execute it. A file with no record does not move.

**C0.4 — The migration tool.** `tools/migrate_module.py --id <source>`. One atomic operation, per D10:

1. capture the "before" result artifacts named in the manifest;
2. `cp source deprecated/code/<name>.py` (refuse if it already exists);
3. write the cleaned copy to `target` — dead symbols from the manifest stripped, `from casim.numerics import ...` substituted, `from casim.constants import ...` substituted;
4. leave a deprecation shim at `source` (`from casim.engine.<...> import *` + `DeprecationWarning`) — removed wholesale at C9;
5. register the module in the owning subpackage's `registry.py` (D11);
6. re-run the named baselines and **abort + roll back on any drift**;
7. update the manifest record with `migrated: <timestamp>` and the drift result.

**C0.5 — Scaffolding.** Create `deprecated/code/` and `deprecated/tests/` with READMEs stating the acceptance rule (nothing lands here without a manifest record or a ledger reason). Extend `deprecated/README.md`.

**Acceptance gate C0**

- The manifest covers **171 of 171** files; a coverage assertion is in `make gate`.
- Every manifest `target` is unique and every `sector` is one of the seven.
- `tools/migrate_module.py` migrates one trivial leaf module end-to-end (suggested: `ca_lazy.py` or `ca_si_scale.py`), gate stays green, `make drift` clean, and `--rollback` restores the tree exactly.
- A deliberately corrupted clean (delete a live symbol) **aborts the migration** rather than landing.

**Handoff:** C1 and C2 are independent of each other and both are independent of C3+. Recommended order C1 → C2 → C3, because C2's literal deletion is cleanest once the numerics façade has already touched every file.

### C1 — The numerics façade (D8)

*One session. Absorbs P2.2, P2.3, and P2.4 from the P-roadmap.*

**Entry state:** C0 complete. 164 files import numpy/scipy directly; 266 `np.fft.*` call sites across 38 modules; `casim.lattice.backend` has zero physics importers.

**Read first:** this file §2 D8; `roadmap-unified-program.md` §P2; `src/casim/lattice/backend.py`; `ca-simulation/ca_fft.py`; `tests/casim/test_fft_backend_equivalence.py`; `docs/status/P1-completion-overview.md` §P2.1.

**Deliverables**

**C1.1 — `src/casim/numerics/`.** A single import surface:

```python
from casim.numerics import xp, fft, linalg, rng
```

- `xp` — the array namespace (numpy today; MLX/CuPy later). Not an alias for numpy: a protocol with a numpy implementation.
- `fft` — absorbs `ca_fft` in full, including the P2.1 threading fix and plan keepalive. Adds `rfftn`/`irfftn` for the real-valued $\mathbf E$, $\mathbf B$ fields that currently pay full complex transforms.
- `linalg` — the scipy surface actually in use, enumerated from C0.1 rather than guessed. `np.einsum('...ij,...jk->...ik')` gets a `batched_matmul` that dispatches to BLAS `zgemm` (P2.5's second item, and it belongs here not there).
- `rng` — per-channel seeded generators, closing the "one global RNG" gap (P4's last row, deliverable early because it is free here).
- `chiral_transform` — carried over from `backend.py`, with its own regression. **Chiral transforms are the known hazard** (CLAUDE.md: numpy/scipy may drop real or imaginary parts). The façade is the right place to own hand-written replacements if the vendored ones misbehave; the equivalence test must specifically cover real/imaginary preservation.

`src/casim/lattice/backend.py` becomes `casim/numerics/backends/` and keeps its seven-method protocol.

**C1.2 — The equivalence contract, extended.** `tests/casim/test_fft_backend_equivalence.py` already holds the bar (all libraries agree to $10^{-12}$ relative; round-trip is identity; thread count cannot change the result). Add: `rfftn` agrees with `fftn` on real input; `batched_matmul` agrees with `einsum` bit-for-bit; `chiral_transform` preserves both components. Every future backend meets this before it ships.

**C1.3 — Migration, highest value first.** Order from `roadmap-unified-program.md` §P2.2, now manifest-driven: `poisson_open.py` (8× zero-padded grid, every gravity scenario) → `ca_multigrid.py` (~3000 unthreaded transforms per `solve_hydrogen`; `_k2` rebuilt every call) → `ca_colour_dielectric.py` (23 sites) → `ca_gluon.py` (10 sites, heaviest per-tick state). Then `src/casim`'s 17 files. Then the rest as C3–C6 touch each file anyway.

Fix in the same pass: `src/casim/lattice/chiral_core.py:31` imports `ca_fft` directly, bypassing the seam it registers itself with; and `chiral_core.py:84-86` rebuilds `make_kgrid_3d` *and* the full unitary on every call, a straight regression against the kernel it claims to match bit-for-bit.

**C1.4 — Caching and allocation (P2.3).** Preallocated FFT scratch, in-place transforms. Extend the k-grid/dispersion caching `ca_bcc` (`_weyl_cache`) and `ca_wmu` (`_disp_cache`) already do to the modules that lack it. This directly attacks the `_FFT_OVERHEAD = 3.0` fudge at `src/casim/suite/tiers.py:40`.

**C1.5 — The ratchet.** `tools/audit_numerics.py --ratchet`, same pattern as P1.3's: counts direct numpy/scipy/`ca_fft` imports outside `casim.numerics`, fails on regression, `--list` names the files. Starts at 164 and only goes down. Wired into `make gate`.

**C1.6 — A second backend (P2.4, D4).** MLX or JAX-metal for Apple Silicon. Generalise the existing pattern rather than reinventing — `ca_wmu.py:754-802` already has a JAX path covering two functions, unreachable only because JAX is not a declared dependency. Ship as an extra (`.[metal]`), never a hard dependency, following P2.1's lesson.

**Precision holds at complex128.** `float32` eps ($1.2\times10^{-7}$) is five orders above the `machine` class's $10^{-12}$ gate; that gate is the product, not a tunable.

**Acceptance gate C1**

- `make drift` clean across all 392 artifacts after the migration — **bit-identical**, not "within tolerance."
- Numerics ratchet installed and green; count strictly below 164.
- A second backend passes the full C1.2 contract.
- ≥ 3× wall-clock on the reference scenario set (`photon_pair`, `weyl_bcc`, `gluon_bcc`, a gravity scenario), measured and recorded in `scenarios/RUN-GUIDE.md`.
- Swapping the backend via env var visibly changes the reported backend and changes no result.

**Handoff:** `casim.numerics` is now the substitution target for step 3 of `migrate_module.py`. C3–C6 migrations get D8 compliance for free.

### C2 — Constants inversion (D7)

*One session. Flips the registry from describing values to owning them.*

**Entry state:** C0 complete; C1 recommended but not required. 20 constants registered, 43 sites recorded, 31 statically enforced, 12 unenforceable (re-exports, function default arguments like `gap_solve(..., Lam3=0.347)`, runtime-computed values).

**Read first:** this file §2 D7; `src/casim/constants/__init__.py` (the docstring states the D2 position this phase reverses); `tests/casim/test_constants_consistency.py`; `docs/status/P0-completion-overview.md` §P0.1–P0.2.

**Deliverables**

**C2.1 — Registry owns values.** `Constant` gains an authoritative `value` (already present) and modules import it:

```python
from casim.constants import c_lat, G_LATTICE, delta_star
```

Exact constants resolve from closed form, not a literal: $a/\ell_P = \sqrt{8\pi}\,3^{1/4}$, $c_\text{lat} = 1/\sqrt3$, $\delta^* = 2/9$ as a `Fraction`, $G_\text{LATTICE} = 1/(72\pi)$, $W = 6\lambda_6$. A `Fraction`-valued constant exposes both the exact object and a float; tests asserting exactness use the former.

**C2.2 — The three hard cases keep their honesty.** P0's central design call survives inversion unchanged:

- `f_pi` stays **three** constants — 92.07 model anchor, 92.4 PDG target, 92.28 Γ-convention. Collapsing the first two turns a prediction into an input.
- `sin²θ_W` stays **two** — F45 UV $1/4$ and F49 on-shell $2/9$, reconciled by F231. A module importing the wrong one is now a *type* of error the registry can catch, which it could not before.
- `cos 3δ*` stays **two** — derived $\cos(2/3) = 0.7858873$ and empirical F93-O7 $0.785874$. The $1.7\times10^{-5}$ gap **is** the F256 near-coincidence.
- `alpha_eff_star` stays a **bracket** $[0.376, 0.411]$ with no scalar value. Any module that wants a number must ask for an endpoint explicitly, which is the correct friction.

**C2.3 — The `@measured` escape hatch.** Some modules must *compute* a constant because the derivation is the physics under test — `derive_velocity_addition.py` at $1/\sqrt2$ (2-D square lattice), `forks/curl_fork_cubic.py` at $1.0$ (simple-cubic fork whose emergent light speed is the quantity under test), and every `c_lat` that emerges from a dispersion fit. These register as `MeasuredConstant(symbol, compares_to="c_lat", reason=...)` and are **enumerated, not allowlisted by regex.** P0's allowlist becomes a typed declaration.

**C2.4 — The consistency test flips polarity.** `tests/casim/test_constants_consistency.py` currently asserts *every recorded site agrees with the registry*. After C2 it asserts *no unregistered numeric literal matching a registry value exists anywhere in `src/` or `ca-simulation/`.* The 12 unenforceable sites become enforceable because the pattern they hid behind (function default arguments) is exactly what disappears when the value comes from an import.

**C2.5 — Complete the registry.** Add the constants P0 recorded as sites but never registered as owners, and the ones the sweep will surface once the polarity flips. Known gaps: $\lambda_6 = 0.243$ (nowhere a named module constant — recomputed in each derive script, compared against a literal target inside a test), $M(0) = 311$ MeV in three unit systems, $\Lambda^{(3)} = 347$ MeV, $m_D$, the QCD calibration block from the 2026-06-06 audit.

**Acceptance gate C2**

- `grep -rn "1/np.sqrt(3)\|0.5773502691896258" src/ ca-simulation/` returns **only** `casim/constants/geometry.py` and declared `MeasuredConstant` sites.
- Changing `c_lat` in the registry moves a **named, countable** set of tests — recorded in the phase's changelog entry as a number.
- `make drift` clean: the closed-form resolutions must reproduce the truncated literals they replace, or the difference is recorded (the $a/\ell_P$ case is known — 5-significant-figure `6.5978` carries $3.4\times10^{-6}$ relative error, and P0 already holds two sites to their own precision).
- Every registered constant still has a finding. Every `MeasuredConstant` has a reason.

**Handoff:** step 3 of `migrate_module.py` now substitutes constants as well as numerics. C3–C6 migrations get D7 compliance for free.

Module(
    name="lattice.bcc", path="src/casim/engine/lattice/bcc.py",
    sector="lattice", findings=("F41","F175","F264"),

Each subpackage self-registers on import. This is the data `casim index` consumes at C8 and the field that answers P6's reachability question permanently.

**C3.3 — BCC as the base layer.** Migrate, in this order, via `migrate_module.py`: `ca_lattice.py`, `ca_bcc.py`, `ca_core.py`, `ca_core_exact.py`, `ca_fft.py` (→ already folded into `casim.numerics` at C1 — the manifest records it as absorbed, not moved), `ca_bcc_gauge.py`, `ca_blockspin.py`, `ca_multigrid.py`.

**Two known defects to resolve while here, not later:**

- `ca_blockspin.block_average` float-casts and drops the imaginary part, which is why `engine/blockspin.py:49-62` reimplemented it natively. Both exist and only one is right. Fix the kernel or formally deprecate it — do not migrate both.
- Cubic lattice code moves to `engine/lattice/cubic.py` and is explicitly labelled **reference implementation, retained as the continuum-limit regression target** (D1). It is not deleted and it is not canonical.

**C3.4 — Shim discipline.** Every migrated module leaves a shim at its `ca-simulation/` path emitting `DeprecationWarning`. `make gate` gains a check that no *new* code imports a shim path. Shims are removed wholesale at C9, never one at a time.

**Acceptance gate C3**

- `make gate` green; `make drift` clean; the full battery runs with no import errors.
- Every module in `engine/` is in the module registry; a registry-coverage assertion is in the gate.
- `casim list-channels` output unchanged.
- Deleting a shim breaks nothing in `src/` (i.e. `src/` has already fully moved off the old paths); it may still break `tests/`, which is C7's problem.

**Handoff:** C4, C5, and C6 are independent of each other and may run in any order or in parallel sessions — **provided each session claims its sector in the manifest before starting.** Concurrent-session collisions have happened three times in this project (F110, F129, F262).

### C4 — Sector migration: gauge fields

*One session. ~25 modules.*

**Entry state:** C3 complete; base layer in `engine/lattice/`.

**Read first:** the manifest records with `sector: gauge`; `roadmap-unified-program.md` B1 (topology partition) and §P3.1; findings F67/F68/F69 (paired-spinor photon), F91 (propagator classification), F250 (all-$k$ gauge pole), F264.

**The largest cleanup in the roadmap lands here.** `ca_maxwell.py` carries the **superseded σ-bilinear photon** — helicity↔branch, birefringent, excluded by GRB/AGN polarimetry (F65/F66/F67). Per the ledger it is *partially* superseded: the σ-bilinear **field construction** is retained for the massive and non-Abelian sectors (W/Z/gluon), which are not under the polarimetry bound. So the clean is surgical: the photon *channel* dies, the field *construction* moves to `engine/gauge/bilinear.py` with a docstring stating exactly which sectors may use it. Likewise `gluon_rotation_step_spectral_bcc_chiral` — retained as the pre-2026-06-04 comparison object, not as a live propagator.

**Do not attempt P3.1's BCC port here.** C4 moves files; the cubic→BCC *physics* port (`photon_pair`, `w_chiral`, `z_even`, `charge_photon`) is P3.1 of the other roadmap and must be preceded by its derivation spike. C4 makes that port a single-tree operation instead of a cross-tree one.

**Acceptance gate C4:** every `sector: gauge` manifest record is `migrated`; `make drift` clean; the σ-bilinear photon channel is gone from live code and present in `deprecated/code/`; `casim list-channels` unchanged; module registry complete for the sector.

### C7 — The test registry (D9)

*Two sessions, realistically. The phase with the most leverage and the most surface area.*

**Entry state:** C0–C6 complete; all physics in `casim.engine`. 345 test files, 320 doing work at import, 232 with no assert, 70 with no failure mode at all.

**Read first:** this file §2 D9; `docs/status/P1-completion-overview.md` (all of it — the baseline engine, the manifest, the ratchet, and the honest PARTIAL on the RAN criterion); `src/casim/suite/runner.py`; `src/casim/baselines.py`; `test-results/manifest.json`.

**Deliverables**

**C7.1 — The record format.** `tests/registry/<sector>.yaml`:

```yaml
- id: F234-Wvc-triple-closure
  finding: F234
  sector: lepton
  kind: assertion            # assertion | result_dump | scenario | legacy_script
  module: casim.engine.particles.lepton_shape
  entry: check_triple_closure
  params:
    delta_star: 2/9
    B_F95: -5.69e-2
  expect:
    exactness: exact
    tol: 0
  results: test-results/F234_Wvc.json
  tier: gate                 # gate | battery | archive
  superseded_by: null
```

**Four kinds, two result contracts** (the structure the ask calls for):

| Kind | Contract | Failure mode |
|---|---|---|
| `assertion` | returns `bool` / raises | direct |
| `result_dump` | returns a dict → written to `results:` | **baseline diff vs git HEAD** (P1's engine, unchanged) |
| `scenario` | a YAML run + `expect:` gates | observable outside tolerance |
| `legacy_script` | wraps an unmigrated file | whatever it had — **declared debt** |

`legacy_script` is the migration ramp: **every one of the 345 files gets a registry record on day one**, so coverage is 100% immediately and the work is visible as a countable `legacy_script` count that a ratchet drives to zero. This is how C7 avoids being a 345-file big bang.

**C7.2 — `casim test` becomes the only runner.** New selectors:

```
casim test --id F234-Wvc-triple-closure
casim test --finding F234
casim test --sector lepton
casim test --kind assertion
casim test --tier gate
casim test --exactness exact
casim test --param delta_star=2/9        # parameter sweep over a registry entry
```

`--param` is the ask's core: *a test is a parameter setting run through CASIM.* Overriding a registry `params:` value runs the same entry point at a different point in parameter space and diffs against the declared expectation — which makes sweeps and sensitivity analysis a first-class operation instead of a copy-pasted script.

**C7.3 — pytest delegates.** A single collector (`tests/conftest.py`) generates pytest items from the registry, so `pytest` and `casim test` run **the same objects** and cannot diverge. The six existing invocation conventions collapse to one. P0's `superseded` / `historical_baseline` markers become registry fields.

**C7.4 — Import-time side effects die structurally (P1.3).** A registry entry names a module *and an entry function*. Physics at import is impossible for a migrated test — not by discipline, by construction. This is why P1 deliberately shipped the ratchet instead of a rushed 320-file refactor: the refactor is free once the registry exists.

**C7.5 — The 70 unfalsifiable tests.** Each migrates to `assertion` (a real claim, ~30 of them are clean algebraic identities) or `result_dump` (emit numbers, diff them). A registry record **cannot** declare neither. The P1 ratchet gains a fourth counter — `legacy_script` — and the P1 PARTIAL on the "zero in RAN limbo" criterion is finally closed here, honestly, rather than by relabelling.

**C7.6 — Dead and superseded tests move out.** Per the ask: `deprecated/tests/`. The rule is the same as C0.2's — the ledger and the registry propose, a human accepts. **P0's lesson applies with full force:** of 14 files an audit called superseded, one was superseded wholesale, eleven were partial (a dead verdict wrapped around live, load-bearing algebra), and one — `test_F91_pairing_classification.py` — *is the supersession authority*. Only `fully_superseded` files move; partial files stay live with their banners.

**Acceptance gate C7**

- Every one of the 345 test files has a registry record; a coverage assertion is in `make gate`.
- `pytest` and `casim test --tier gate` produce identical pass/fail sets.
- `casim test --param <k>=<v>` runs a registry entry at a perturbed value and reports the drift.
- Ratchets: `legacy_script` count recorded and falling; `unfalsifiable` at **0** for migrated entries; `import_time_work` strictly below 320.
- Perturbing a registry constant fails a **named, countable** set of registry IDs — reported by ID, not by scraped filename.
- Dead tests are in `deprecated/tests/` with a ledger reason each.

**Handoff:** C8 consumes both registries. Nothing else blocks on C7.

## 6. Sequencing

```
C0 ──┬──> C1 ──┬──> C3 ──┬──> C4 ──┐
     │         │         ├──> C5 ──┼──> C7 ──> C8 ──> C9
     └──> C2 ──┘         └──> C6 ──┘

           P3 (one lattice, one clock)  ──> unblocked by C3, runs after C4–C6
           P4 (scenario v2), P5 (GUI)   ──> after P3
```

- **C0 blocks everything.** No file moves before the manifest exists.
- **C1 and C2 are independent** and can be done in either order or in parallel sessions. C1 first is marginally better: it touches every file anyway, so C2's literal deletion rides along.
- **C4, C5, C6 are independent** given C3. Parallel sessions are fine **if each claims its sector in the manifest first.**
- **C7 needs C6** — a test registry pointing at `ca-simulation` paths would have to be rewritten.
- **C8 needs C3, C6, and C7** (it consumes both registries).
- **The P-roadmap's P3 (one lattice, one clock) is unblocked by C3** and should run after C4–C6. It is the physics end state; this roadmap is the structure that makes it a single-tree operation.
- **P6 (kernel coverage) dissolves into C6 + C8** — reachability becomes a registry field rather than a survey.

**Critical path: C0 → C3 → C6 → C7.** C1, C2, C4, C5, C8 can each slip a session without moving the end state.

## 7. Risks

| Risk | Severity | Mitigation |
|---|---|---|
| **A migration silently changes a verified result.** 171 files, most unread in months, moving under a cleanup that strips symbols. | **High** | `migrate_module.py` re-runs the manifest's named baselines and **rolls back on any drift**. Bit-identical is the bar. This is precisely what P1's baseline engine was built for; C-phases are its first real use. |
| **A surgical clean removes live algebra.** P0 found that 11 of 14 "superseded" files were partial — a dead verdict wrapped around load-bearing code. C4–C6 do this across the whole tree. | **High** | C0.2 *proposes*, a human *accepts*, per file. The ledger's "what survived" field is authoritative. Never blanket-strip by keyword. When in doubt, migrate with a banner (the `derive_generator_norm_from_F118.py` pattern) rather than delete. |
| **Constants inversion changes a number.** Closed forms replace truncated literals; $a/\ell_P$ alone moves by $3.4\times10^{-6}$ relative. | Medium | C2.3's `MeasuredConstant` and P0's per-site `expected` override both already exist for exactly this. Every difference is recorded with a reason or the phase does not pass. |
| **The numerics façade changes round-off.** Different FFT libraries differ in the last bits — invisible in most codebases, fatal in one whose product is a $10^{-12}$ gate. Chiral transforms are a known numpy/scipy hazard. | Medium | C1.2's contract, extended specifically to real/imaginary preservation. Where a difference is real, record the tolerance rather than hide it. CLAUDE.md's standing instruction to hand-write chiral primitives if the vendored ones misbehave applies here. |
| **C7 is very large.** 345 files, and the registry could become a second place to specify the same thing. | Medium | `legacy_script` gives 100% coverage on day one and converts the size into a falling counter. The registry is the *only* specification — pytest delegates to it (C7.3), so divergence is structurally impossible. |
| **Concurrent-session collisions.** Already happened three times. C4/C5/C6 explicitly invite parallel sessions. | Medium | Sector claim in the manifest before any work. C8.2's max-F check. One session, one sector, no exceptions. |
| **Scope creep into physics.** C4 sits next to P3.1's BCC port; C6 sits next to P6's kernel wrapping. | Low | Stated explicitly in each phase: C-phases move and clean files. They do not port physics. P3.1 needs its derivation spike first and is not this roadmap's business. |
