# C3 completion overview — engine skeleton and the BCC base layer

*2026-07-30 - 14:10. Phase C3 of `docs/roadmaps/roadmap-casim-consolidation.md` (decisions D1, D6, D11). Entry state: C0–C2 complete, `make gate` green. No physics reversed; this is the structural move C0's instruments were built to make safe.*

## What landed

**C3.1 — the sub-sector tree exists, and the engine spine moved into it.** Created `engine/{core,lattice,gauge,particles,interactions}/` per roadmap §4. The nine flat `engine/*.py` spine modules (`channel`, `observers`, `simulation`, `channels`, `coupled`, `tier3`, `spectral_matter`, `blockspin`, and the F212/F214 entanglement register) moved into `engine/core/`. The entanglement channel — previously `engine/manybody.py`, whose `EntanglementRegisterChannel` is the live 2ⁿ register — was renamed `core/entanglement_register.py` to resolve the one genuine target-path collision: the migration manifest maps the *kernel* `ca_manybody.py` (the Hartree multi-nucleon/multi-electron solver) to `core/manybody.py`, and two different modules cannot share it. The `src/` package layer (`casim.lattice`, `casim.particles`, `casim.gui`, `casim.verify`, plus `engine/__init__`) was rewired to the new `engine.core.*` paths; **module-alias shims** left at each old flat `engine/<name>.py` keep the unmigrated test battery importing, removed wholesale at C9. `casim.engine`'s public API (`Simulation`, `Channel`, `LatticeSpec`, …) is unchanged, and `casim list-channels` is **byte-identical** before and after.

**C3.2 — the module registry (D11).** `src/casim/engine/registry.py` mirrors `casim.constants`: a frozen `Module` record (name, path, sector, findings, exactness, reachability, tests, results, role, origin) and a registry populated from two sources — migrated kernels are read from the migration manifest the moment their target file lands under `engine/` (so the registry stays in lock-step with the migration rather than being a second thing to sync), and the pre-existing engine spine, which has no manifest record, is declared by hand. This is the data `casim index` consumes at C8 and the field that turns P6's reachability question into a query (`[m.name for m in all_modules() if m.reach != "driven"]`). A coverage assertion — every real module under `engine/` has a record — is wired into `make gate` as `tools/check_module_registry.py`. 27 modules registered (9 spine + 18 migrated), full coverage.

**C3.3 — the base layer migrated.** All **18** `phase: C3` manifest records migrated into `engine/lattice/` (bcc, geometry ←ca_lattice, core, core_exact, multigrid, blockspin, poisson_open, si_scale, curved, and the three block-spin binding/dynamical/baryon kernels) and `engine/core/` (manybody, lpt_generator, and four `_viz_*` helpers). Every migration is D10: the pre-clean original is backed up under `deprecated/code/` with a header, the cleaned copy lands at the new path, a `DeprecationWarning` shim replaces the `ca-simulation/` source, and the manifest record is stamped.

**Two known defects resolved, not carried forward.**

- `block_average` (kernel) force-cast to `float64` and **silently dropped the imaginary part** — the reason `core/blockspin.py` reimplemented it natively. The kernel entry point is now dtype-preserving: real input is **bit-identical** to the old `astype(float64)` (verified), complex input keeps `Im(f)`. Each function is now correct for its contract (the kernel is the real-scalar cube blocker; `core.blockspin.block_average_field` remains the complex/spinor engine path with the leading component axis), and neither silently corrupts. No result moves.
- The simple-cubic / square-lattice code (`core.py`, `core_exact.py`, and `geometry.cubic()/square()`) is now **explicitly labelled REFERENCE implementation, continuum-limit regression target, not canonical (D1)**. It deviates from the roadmap's §4 prose (a dedicated `cubic.py`): the manifest — authoritative for file moves — has no `cubic.py` target, and splitting the reference out of `geometry.py`/`core.py` is a code-*split*, not a file-*move*, which C-phases explicitly do not do. Labelled in place; the extraction is deferred with this note.

**C3.4 — shim discipline.** `tools/check_shim_imports.py` (in `make gate`) asserts no `src/casim/` file imports a migrated shim: neither a migrated `ca-simulation` kernel by its old bare name (once stamped) nor a flat-engine shim (`casim.engine.channel` → `engine.core.channel`). The forbidden set is read from the manifest, so the check tightens automatically as C4–C6 migrate more kernels. Not flagged, because they are the roadmap's intended transitional state cleared at their own phase: an unmigrated kernel importing a sibling shim, and the shim files themselves. All `src/casim` import statements for the 18 kernels + `ca_fft` were rewired off the shims; the only import-time shim warning left is `ca_gravity` (a C6 kernel) → `ca_fft`, which clears at C6.
